# Deep Search Pro 个人本地工作台设计

日期：2026-10-16

## 已确认方向

个人本机使用，前后端独立工程与进程。采用已确认的 A 方案：浅色背景、鼠尾草绿色强调色、三栏工作台。左侧管理会话，中间显示对话与输入框，右侧显示真实执行进度和会话文件。右侧可折叠，小屏以抽屉展示辅助面板。

## 目录、启动与技术栈

```text
D:\deep-search-pro-master\
├── deep-search-pro-master-be\
├── deep-search-pro-master-fe\
└── docs\superpowers\specs\
```

保留现有后端位置、虚拟环境和模型配置。后端默认监听 127.0.0.1:8000，前端开发服务器监听 127.0.0.1:5173。开发时通过 Vite 代理 /api 和 /ws。静态预览使用显式后端地址及受限本地 CORS 来源，README 提供对应启动方式。

前端采用 Vue 3、Vite、严格模式 TypeScript、Vue Router、Pinia、Tailwind CSS 4、Lucide 和 pnpm。使用集中封装的原生 fetch 和类型化 API 模块；独立 composable 管理 WebSocket。组件按会话、对话、进度、文件四个功能划分，避免单文件承担整个工作台。

Pinia 保存跨组件状态；浏览器 IndexedDB 保存会话标题和消息，文件二进制保留在后端磁盘。HTTP 与 WebSocket 数据先校验再进入 store。Markdown 禁用原始 HTML，使用受限 Vue 节点渲染，不直接向 v-html 传模型输出。外链仅接受 http/https。所有服务密钥仅在后端保存。

## 功能与交互

- 新建及切换会话，首条问题自动形成标题，支持复制回答。
- 多轮提问；Enter 发送、Shift+Enter 换行，输入法组合期间 Enter 不提交。
- 选择或拖拽文件上传，显示逐文件结果，失败文件不进入分析。
- 展示真实助手调用、工具开始、任务完成及失败事件。不伪造逐工具耗时、完成状态或百分比。
- 显示完整 Markdown 回答、表格和代码块；首版不做逐字流式输出。
- 文件面板区分上传资料与生成产物，按会话刷新及下载。
- 空白会话提供示例问题，异步界面覆盖加载、空、错误和成功状态。
- 同会话执行时禁止重复提交，可以切换其他会话。

## 会话与任务协议

thread_id 标识会话，run_id 标识一次提问。浏览器生成 UUID 作为 thread_id，后端验证 UUID；每次提问获得独立 run_id。同一会话最多一个活动任务，重复提交返回 HTTP 409。刷新或重连只查询原任务，不自动重复调用模型。

| 接口 | 约定 |
| --- | --- |
| GET /api/health | 服务状态、每次启动变化的实例标识、已配置能力；不返回密钥或调用收费模型 |
| POST /api/task | 验证 query 与 thread_id，返回 HTTP 202、run_id、thread_id、状态 |
| GET /api/tasks/{run_id} | 状态、最终回答或错误、本次运行的事件快照 |
| POST /api/upload | multipart 文件与 thread_id，返回实际保存名称和逐文件结果 |
| GET /api/files?thread_id=... | 返回会话内相对 storagePath、文件名、大小、修改时间与来源 |
| GET /api/download?thread_id=...&path=... | 仅接受会话内相对路径，验证归属后下载 |
| WS /ws/{thread_id} | 连接后发送 ready，以 run_id 和递增 sequence 标识运行事件 |

前端先建立 WebSocket，收到 ready 再提交任务。保留 monitor_event 信封和 session_created、assistant_call、tool_start、task_result、error 事件，增加 run_id 与 sequence；心跳不进入进度列表。后端保留有界事件快照与终态，重连通过任务接口补齐，客户端按序号去重。

任务状态为 queued、running、succeeded、failed、interrupted。一次运行只产生一次终态，模型中间消息不提前作为成功终态。目录准备、文件复制、模型执行和结果保存都纳入异常处理。

任务状态、结果和事件存入本地 SQLite，不要求新增外部服务。事件超过单任务容量时保留最新窗口与明确截断标记，最终回答单独保存。重启时把遗留 queued/running 标记为 interrupted。

## 历史与重启

浏览器展示历史和模型上下文分别管理。首版保留后端 InMemorySaver，模型记忆仅在本次后端进程中有效。前端通过 health 实例标识检测重启，标记旧会话记忆失效，保留历史阅读并引导新建会话。旧 thread_id 不静默作为有记忆会话提交。页面明确提示历史保存在当前浏览器、模型记忆随后端重启重置。

## 配套后端修正

1. 路径统一解析和归属检查，拒绝 ../、会话外绝对路径及链接逃逸；不再通过 CWD 访问其他会话的 updated 文件。
2. 上传支持 txt、md、pdf、docx、xlsx；单文件最大 20 MiB，每次最多 5 个；验证文件名与实际字节数，分块异步写入。重名增加后缀并返回实际名称，避免覆盖生成报告。
3. 文件列表和下载使用会话标识与相对路径，错误采用正确 HTTP 状态码。
4. 保存后台任务引用和同会话运行锁；关闭时受控取消并记录中断。
5. 每会话保存 WebSocket 连接集合，仅移除断开的连接，单连接发送串行化，处理发送失败。
6. 限制本地 CORS 来源，默认仅监听回环地址。
7. 配置缺失的搜索、数据库、RAG 工具不注册；前端显示未配置。已配置不代表远端在线，实际调用错误独立展示。
8. 统一模型配置入口并兼容当前已跑通环境变量，不更改实际模型、地址或 Key。
9. 消除不存在的文件生成助手等提示词冲突；上传资料只在首次导入或内容变化时复制，避免每轮覆盖报告。
10. SQL 表名从服务端列表校验，自定义查询仅允许单条只读语句，限制行数与超时。文档要求数据库账号仅有查询权限，不自动修改外部授权。
11. RAG 临时会话在 finally 清理，处理空助手列表；依据当前 SDK 实际流式语义决定累计回答或增量拼接。

## 错误与恢复

API 提供 error.code 与可展示的中文 error.message，完整异常留在后端日志。区分模型无权限、连接失败、上传超限、任务冲突。失败时保留已收到进度，只有用户主动重试才生成新 run_id。

断线保留内容并提示正在重连，使用有上限的退避和手动重试；通过任务查询核对运行状态，避免无限处理中。

PDF 保留 Windows Word 转换方式。缺少 Word 或转换失败时明确报错，已生成 Markdown 仍可下载。

后端验证路径越界、上传超限、重复任务、准备阶段异常、任务终态、多连接与重连、SQL 拒绝规则；外部模型、搜索、MySQL 与 RAG 使用受控桩。

验收主路径：独立启动前后端 → 新建会话 → 上传文件 → 提问 → 显示真实进度 → 收到回答 → 下载报告。提供两工程 README 和环境变量模板。
